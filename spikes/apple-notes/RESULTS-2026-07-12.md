# Apple Notes Option 1 spike — 2026-07-12

Research evidence for issue #30. This does not select Option 1, 2, or 3.

## Environment

- macOS 26.5.2 (25F84)
- Notes 4.13
- Node.js 24.14.1
- Codex CLI 0.142.5, authenticated with ChatGPT
- Notes automation permission was already granted, so first-permission prompt time was not measured

## Corpus and timing

The run used 63 existing notes plus six isolated, non-sensitive fixture notes.
Only aggregate facts are recorded here.

| Measurement | Result |
| --- | ---: |
| Notes | 69 |
| Notes read successfully | 69 |
| Raw HTML characters | 8,891,382 |
| Attachment objects exposed by Notes | 26 |
| Named file attachments saved | 7 (6.5 MB) |
| Unnamed attachment objects not saveable | 19 |
| Full extraction runs | 25.75 s, 27.42 s, 30.70 s |
| HTML-to-Markdown conversion | 0.06–0.10 s |
| Git add + initial commit | 0.16 s |
| Forme preflight | 0.08 s |

The median measured Option 1 pipeline was 27.42 seconds; the slowest was
30.76 seconds including Markdown conversion. The export directory is a
standalone git-ready mirror with attachments under `_attachments/`.

## Fidelity

| Surface | Result | Evidence |
| --- | --- | --- |
| Plain text, bold, italic, Unicode | Pass | Fixture content survived conversion |
| Heading level | Partial | Text survived; Notes scripting HTML represented the scripted heading as large bold text |
| Folder hierarchy and duplicate titles | Pass | Account/folder paths preserved; stable note IDs prevent collisions |
| Bare URLs | Pass | URL text survived and remains auto-linkable in Markdown renderers |
| Named links | Inconclusive | Script-created named link lost its `href`; no hand-authored named link existed in this corpus |
| Tables | Partial | All cells survived as readable inline HTML tables, not pipe-table Markdown |
| PNG, HEIC, PDF, TXT attachments | Pass for named files | All seven extension-bearing files saved; fixture links resolve inside the mirror |
| Inline image payloads | Pass with normalization | Base64 images were decoded to mirror files so Markdown does not balloon |
| Unnamed/internal attachments | Fail for four objects | Fifteen of 19 failures corresponded to tables preserved in HTML; four objects in three notes had no saveable file or HTML representation |
| Locked/shared notes | Not tested | This corpus had none |

Trying 11 common filename extensions did not recover any of the 19 unnamed
objects. The four objects with no HTML representation are a real silent-loss
risk unless the installer reports and obtains consent for them.

## White-glove result

Option 1's measured time cost is small enough to fit inside a 30-minute session
on this machine. The mirror and git baseline add about 31 seconds, not minutes.
This measurement must not be extrapolated to hundreds of notes without a
first-user-machine stopwatch run.

The complete install is **not demonstrated ready today**. A fixture-only real
install reached the Codex smoke test, retried for 113 seconds, then failed
because the configured model required a newer Codex version. The first scan was
therefore not timed. This is independent of Apple Notes but blocks the same
white-glove session.

For a 07-16–18 rehearsal, a <=30-minute run is realistic only if preflight
upgrades/verifies Codex before the user's clock starts and the operator presents
the unsupported-attachment count instead of claiming lossless migration. The
weekly review still owns the Option 1/2/3 path decision.
