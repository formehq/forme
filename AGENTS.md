# Forme repository working agreement

This file adds repository-specific rules to Zayn's global Codex working
agreement.

## Re-entry

Read [docs/CONTEXT.md](docs/CONTEXT.md) first. Follow its default set and open
conditional contracts only when the work touches that boundary. Historical
packets, reports and evidence are not default context.

For live execution state, reconcile these surfaces in order:

1. the active GitHub issue;
2. the active integration pull request;
3. [docs/CONTROL.md](docs/CONTROL.md);
4. the GitHub Project.

If they disagree, repair the control surfaces before an external or runtime
effect.

## Product and trust boundary

- Preserve the Highest Vision, Owner authorship, Living Project Twin model,
  R1–R4 continuity and the privacy-first human boundary.
- Treat [docs/PRODUCT.md](docs/PRODUCT.md),
  [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and
  [docs/AGENCY-TRUST.md](docs/AGENCY-TRUST.md) as durable meaning, not status
  logs.
- Do not silently turn an Enabler, diagnostic, governance artifact or test
  harness into Product Progress.
- Production, public traffic, provider calls, real/private Guest data,
  credentials, spend, deployment, publication, messaging and merge require
  explicit authority.
- Preserve the fixed-marker R3 action block in the root README. Only its
  approved executor may replace the body.

## Context discipline

- Put mutable status in one active issue/PR and the short cockpit.
- Put durable product meaning in a stable contract only after Owner
  confirmation.
- Put completed chronology in Git history, comments, archive tags or frozen
  evidence—not at the top of active documents.
- Do not edit byte-frozen Gate A/B material for tidiness. See
  [docs/HISTORY.md](docs/HISTORY.md).
- A repairable failure inside an approved outcome envelope is ordinary work.
  Return only for a genuine boundary change, ambiguous effect or exhausted
  budget.

## Completion

Validate in proportion to risk, report the user-visible capability delta
first, and distinguish local Green from remote CI, integration and Owner
acceptance.
